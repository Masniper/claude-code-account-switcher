# Резервная копия и перенос

[← README](../../README.ru.md) · [English](../backup.md)

`claude-acc backup` записывает аккаунты и файлы агента из проектов в один зашифрованный файл и восстанавливает их на другой машине, в том числе с macOS на Windows. Учётные данные в архив не попадают: после восстановления в каждый аккаунт нужно войти заново.

## Что попадает в архив

| | |
| --- | --- |
| **Переносится** | `settings.json`, `CLAUDE.md`, навыки, агенты, команды, правила, стили вывода, `history.jsonl`, `projects/` (транскрипты, транскрипты субагентов, память), `todos/`, `plans/`, `file-history/` (чекпоинты), `agent-memory*`, `.claude.json` каждого аккаунта (список проектов, MCP-серверы, настройки), привязки к директориям и аккаунт по умолчанию. Из проекта: `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `.mcp.json` и всё внутри `.claude/` и `.agents/`, включая файлы, которые игнорирует git |
| **Убирается как секреты** | `.credentials.json`, `.session_ingress_token`, `hfi-auth.json`; `primaryApiKey` и `oauthAccount` из `.claude.json`; `headers` каждого MCP-сервера; значения `env`, в имени которых есть `KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `AUTH`, `CREDENTIAL` или `COOKIE`, в настройках и конфигах MCP. Резервная копия перечисляет каждое убранное поле по имени, но не по значению |
| **Установить заново** | `plugins/` и `cowork_plugins/`: git-клоны и загрузки с путями этой машины внутри. А также любые `node_modules` |
| **Остаётся на месте** | Кэши, логи, телеметрия, снимки оболочки, реестры живых сессий (`sessions/`), блокировки, PID-файлы и сокеты, checkout'ы в `.claude/worktrees` и собственный кэш личностей этого инструмента |
| **Не входит** | Исходный код проекта. Скопируйте или склонируйте его сами |

Список того, что остаётся на месте, следует собственным спискам машинного состояния Claude Code 2.1.309. `backup create --dry-run` печатает каждую пропущенную запись.

## Три вида резервной копии

| Нужно | Команда |
| --- | --- |
| Все аккаунты целиком | `claude-acc backup create env.ccbackup` |
| Некоторые аккаунты | `claude-acc backup create work.ccbackup --account work --account default` |
| Один проект с его сессиями и памятью из всех аккаунтов | `claude-acc backup create app.ccbackup --project ~/work/app` |
| Всё вместе | `claude-acc backup create all.ccbackup --all-accounts --project ~/work/app` |

Добавьте `--dry-run` к любой из них, чтобы увидеть аккаунты, проекты, число файлов, размер и каждую пропущенную запись, ничего не записывая.

Сначала закройте Claude Code. Если файл меняется во время чтения, резервная копия завершается ошибкой, а не получается несогласованной.

У восстановления те же три режима:

- без `--account` и `--project` восстанавливается всё;
- только `--account` восстанавливает эти аккаунты;
- только `--project` восстанавливает эти проекты, а их сессии и память кладёт в одноимённые аккаунты.

`claude-acc backup inspect FILE` проверяет все контрольные суммы и показывает, что лежит в копии.

## С Mac на Windows

Допустим, на Mac проекты лежат в `/Users/me/work`, а на Windows будут лежать в `F:\work`.

На Mac:

```sh
claude-acc backup create ~/env.ccbackup --all-accounts --project ~/work/app --dry-run
claude-acc backup create ~/env.ccbackup --all-accounts --project ~/work/app
```

На Windows, в PowerShell, после [установки](install.md) Claude Code и claude-acc и копирования исходников в `F:\work`:

```powershell
claude-acc backup inspect F:\env.ccbackup
claude-acc backup restore F:\env.ccbackup --map /Users/me/work=F:\work --dry-run
claude-acc backup restore F:\env.ccbackup --map /Users/me/work=F:\work
```

`--map FROM=TO` переписывает начало пути, только по целым именам папок: `/Users/me/work/app/sub` становится `F:\work\app\sub`, а `/Users/me/workshop` не трогается. Он используется для:

- **Папок сессий.** Claude Code ищет транскрипты и память проекта в `projects/<имя папки, построенное из её пути>`. Эти папки переименовываются под новый путь, `-Users-me-work-app` в `F--work-app`, вместе с транскриптами субагентов и памятью.
- **Списка проектов в `.claude.json`**, ключи которого — пути.
- **Привязок к директориям.**
- **Корней проектов**, если `--project SRC=DIR` не указывает собственную папку.

Содержимое транскриптов никогда не переписывается. Старые пути внутри разговора остаются как были.

Пробный запуск перечисляет каждый файл, который будет записан (`+`), каждый конфликт (`!`), всё, что нельзя записать здесь (`x`, с причиной), каждую переименованную папку сессий и настройки, где упомянуты команды или пути старой машины (хуки, `statusLine`, команды MCP-серверов). Эти настройки не меняются: проверьте каждую вручную.

Затем:

1. Войдите в каждый аккаунт: `claude-acc login <name>`, а для стандартного — `claude` → `/login`.
2. Установите плагины заново.
3. Верните убранные секреты, которые перечислила копия.
4. Проверьте сессию: `cd F:\work\app`, затем `claude --resume`.

По возможности восстанавливайте до входа на новой машине. Вход создаёт `~/.claude.json`, и восстановленный файл потом с ним конфликтует.

Аккаунты никогда не сливаются. Если на Windows уже есть аккаунт с тем же именем, восстановление останавливается; восстановите его под другим именем: `--account work=work-mac`. Исключение — восстановление только проекта: оно добавляет сессии этого проекта в существующий одноимённый аккаунт.

## Навыки и агенты для другого проекта

```sh
claude-acc backup restore app.ccbackup --reuse --project /Users/me/work/app=D:\other --select skills/deploy --select agents/review.md --dry-run
```

`--reuse` берёт из `.claude/` и `.agents/` проекта только `skills`, `agents`, `rules` и `commands`. Его настройки, состояние, чекпоинты, память, сессии и аккаунты остаются в стороне. `--select` сужает выбор до этих путей. Без `--select` берутся все четыре вида.

## Конфликты, повторный запуск и прерывания

- **Существующие файлы** не перезаписываются без `--replace`. Файл с тем же содержимым считается уже восстановленным.
- **`--replace`** сначала сохраняет каждый оригинал в `~/.claude-switch/restore-backups/<run>/originals/`.
- **Повторный запуск** ничего нового не пишет. Аккаунт, созданный прошлым восстановлением той же копии, помечен, поэтому он узнаётся, а не отвергается.
- **Прерывания.** Каждый шаг записывается в журнал до того, как выполнен. Восстановление, завершившееся ошибкой, отменяет сделанное. Если процесс был убит, следующее восстановление не запустится, а `claude-acc backup rollback` отменит прерванное.

## Безопасность

- **Шифрование.** Файл — это файл [age](https://age-encryption.org), зашифрованный паролем (scrypt), поэтому без пароля не прочитать ни имена файлов, ни манифест.
- **Целостность.** SHA-256 каждого файла проверяется до любой записи. Повреждённый, обрезанный или подменённый архив отвергается.
- **Пароль.** Читается с терминала без эха или одной строкой из stdin, когда это не терминал. Никогда не из аргумента и нигде не записывается.
- **Распаковка.** Архив расшифровывается в закрытую папку внутри `~/.claude-switch`, которая потом удаляется. Запись с абсолютным путём, с `..` или ссылка за пределы своей папки отвергаются.
- **Вывод.** Всё, что печатается, — пути, числа, имена аккаунтов и полей. Содержимое файлов — никогда.

## Ограничения

- **Продолжение сессий на Windows пока не проверено.** Переименованные папки следуют собственному правилу именования Claude Code, поэтому `F:\work\app` становится `F--work-app`, но на настоящей Windows-машине перенесённую сессию ещё никто не продолжал. Проверьте одну, прежде чем полагаться. Claude Code строит имя папки из пути ровно так, как записывает рабочую директорию, поэтому буква диска в другом регистре (`f:` вместо `F:`) даёт другую папку.
- **Символьные ссылки** на Windows не создаются: для них нужен режим разработчика. Каждая перечисляется; скопируйте то, на что она указывает, вручную. На macOS и Linux восстанавливается относительная ссылка внутри своей папки; любая другая перечисляется.
- **Имена, недопустимые в Windows** (`:`, `?`, `CON`, точка в конце), и два имени, различающиеся только регистром, перечисляются и пропускаются.
- **Сессии, начатые в подпапке проекта**, переносятся вместе с целым аккаунтом, но не с копией только проекта.
- **В zsh-скрипте** (`claude-switch.sh`) нет `backup`: ему нужно шифрование, которого нет в оболочке.
- **Это не полная копия машины.** Исходный код, сам Claude Code и настройки других инструментов не входят.
